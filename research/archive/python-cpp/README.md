# Archived Python and C++ programs of the proof supplement (releases v0.1.0 and v0.2.0)

The programs in this directory were the proof supplement of releases v0.1.0
and v0.2.0 of this repository. As of release v0.3.0 (8 October 2026) they are
superseded by the Go module in `supplement/`, which ships the same computations as a
single standard-library Go module (one `supplement/cmd/<command>` per program, see
`supplement/DEVELOPING.md`). They are kept here, unmodified, at their repository-relative
paths of release v0.2.0 (for example `research/verify_e6_independent.py` is now
`research/archive/python-cpp/research/verify_e6_independent.py`). Git history
keeps them at their original paths up to and including commit `6fe3eab` (the
commit after tag `v0.2.0`, which is `39f1f7e`), and the release archive
`exceptional-leading-proof.zip` of v0.2.0 contains the shipped copies together
with the runner.

## Verification of the Go port

The Go port was written on 8 October 2026 by Claude Sonnet 5.5 agents (one per
program) and each port was reviewed by Claude Fable 5.1 against the reference
outputs of the v0.2.0 supplement, under the author's direction. The port was
verified against these programs:

- certificate for certificate: every certificate regenerated by the Go runner,
  in both modes, is semantically equal to the one regenerated by the v0.2.0
  runner (the only differences are program-provenance keys, such as the hash
  of the program's own source, which cannot agree by construction);
- by differential tests on random pairs: Kazhdan--Lusztig polynomials of random
  pairs in $A_4$, $D_4$, $D_5$, $D_6$ and $E_6$ computed by the Go engines and by
  the C++/Python engines agree (zero mismatches);
- by full element-list comparisons: the complete element and terminal lists of
  the enumeration programs (root-index and integer-matrix searches, the $E_8/D_7$
  classification, the fully commutative catalogues and maxima) agree with the
  Go lists element for element (zero mismatches).

The stable summary `expected-summary.json` of the v0.3.0 archive is
semantically identical to that of v0.2.0; the mathematics did not change.

## Running the archived programs

These copies are a record, not a maintained tool. Most of them locate the
repository root relative to their own file (`Path(__file__).resolve().parents[1]`
or `parents[2]`; the runner and `affine_proof.py` use their own directory), so
they do not run correctly from this directory. To run them, check out tag
`v0.2.0` or extract the v0.2.0 release archive and run `python3 run_proofs.py`
there, with Python 3.10 or later and a C++17 compiler. The archived
`computations/README.md` describes the paths of the v0.2.0 layout.
